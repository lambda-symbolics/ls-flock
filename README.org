#+TITLE: ls-flock
#+STARTUP: content

=ls-flock= provides process-shared advisory file locks over POSIX =lockf=
and Windows =LockFileEx=. The process registry recognizes aliases by file
identity and serializes scoped locks and leases together. On POSIX, open
lock files only through ls-flock: closing any other descriptor on a held
inode can release the process's record lock.

* Scoped locks

#+BEGIN_SRC lisp
(ls-flock:with-file-lock (#P"/var/lib/app/store.lock")
  (rewrite-the-store))

(ls-flock:call-with-file-lock #P"/var/lib/app/store.lock"
                              (lambda () (rewrite-the-store)))
#+END_SRC

Scoped locks wait for other holders. The lock file is created with mode
=0600= (override with =:mode=) and intentionally left behind on release so
later holders can reuse it. Acquisition failures signal =FILE-LOCK-ERROR=;
conditions from the body propagate unchanged and still release the lock.

Use =CALL-WITH-FILE-LOCKS= for an ordered group. It takes each file identity
once, in the order supplied, and releases the acquired subset on failure.

* Exclusive leases

#+BEGIN_SRC lisp
(let ((lease (ls-flock:lease-acquire #P"/var/lib/app/session.lock")))
  (unwind-protect
       (serve-the-session)
    (ls-flock:lease-release lease)))
#+END_SRC

A lease is a process-lifetime exclusive claim acquired without waiting.
When this process already holds a live lease on the pathname, or another
process owns the lock, acquisition signals =FILE-LOCK-BUSY=, a subtype of
=FILE-LOCK-ERROR=. =LEASE-RELEASE= is idempotent, =LEASE-HELD-P= reports
liveness, and a crashed owner's leftover lock file is reusable immediately
because the operating system drops the lock with the process.

=FILE-LOCK-BUSY-OWNER-PID= returns the verified local PID, an observed
foreign POSIX PID when available, or =NIL=. Busy is authoritative even
if no owner PID is available. =FILE-LOCK-BUSY-P= probes an existing file
without creating it by default and returns busy and the optional PID.

Use =:guard-pathname= on both =LEASE-ACQUIRE= and =FILE-LOCK-BUSY-P= when
the lease file should be removed on normal release. All participants must
use the same persistent guard; the probe and release hold it through
identity-checked unlink. Unlink is best effort; if the guard is unavailable,
release still unlocks the file without unlinking it.

A fork child inherits descriptor numbers but none of the parent's POSIX
locks. =RESET-AFTER-FORK= closes the child's copies without taking inherited
mutexes; the first acquisition also detects a PID change. A saved image
instead uses =RESET-AFTER-RESTART= (installed as an SBCL init hook), which
forgets stale numbers without closing them.

* Tests

#+BEGIN_SRC lisp
(asdf:test-system :ls-flock)
#+END_SRC

The cross-process test starts a second SBCL with the same ls-flock source,
waits for bounded readiness, verifies contention, terminates the holder,
and checks stale-file reuse. Run it on native Windows with SBCL on PATH
and a local NTFS temporary directory. Verify foreign owner PID is unknown,
then repeat the ordered-group and busy probes with NTFS hard-link aliases.
The POSIX suite additionally checks real fork and hard/symbolic-link aliases.

* Development

#+BEGIN_SRC sh
./script/bootstrap
./script/check
./script/check --fix
#+END_SRC

=./script/check= runs the tests, then checks the source with
[[https://github.com/lambda-symbolics/cheque][cheque]] as =cheque.sexp=
configures it. =--fix= skips the tests and repairs what cheque can repair.
cheque and its tools are development dependencies: =checks/qlfile= lists them,
and the check installs them on first use into =~/.cache/cheque/tools/=.
